## Обновление скриптом (`deploy/release.sh`)

С версии контента 0.3 релиз выкладывается одним скриптом на хосте: `bash release.sh /tmp/s21-project-lab-<REL>.tgz <REL>`. Скрипт сначала проверяет, не идёт ли на сервисе работа (с `20261007-01`), не перезаписывает существующий релиз, отказывается от архива с `data/`, делает резервную копию тома в `/opt/s21_project_lab/backups/<REL>/`, собирает образ на проверенной базе, до переключения проверяет в новом образе библиотеки, боевой entrypoint и чтение всех сохранённых запусков, диалогов и черновиков, проходит в нём весь маршрут контента без моделей (`smoke.py`, с `20261007-01`), затем переключает контейнер и ждёт ответа 401 без сессии. Если ответа нет, возвращает предыдущий релиз. Ссылка `current` переводится только после успешной проверки. Команды отката скрипт печатает в конце.

На боевом сервере страницы, открытые генератором контента (поиск ссылок), проверяются кодом: открываются только публичные адреса http/https на портах 80/443, каждый редирект проверяется заново — чтобы ссылка из ответа поиска не могла обратиться к самому серверу, внутренней сети или адресу метаданных облака.
