# Перевод архива проекта и новые форматы документов

Дата: 2026-10-26 · Ветка: auditor-branch-dashboard · Статус: согласовано, план работ не написан

## Зачем

Методист переводит учебные проекты Школы 21 целиком, а не по одному файлу.
Проект — это репозиторий: `README.md`, `check-list.yml`, `TAGS_FILES.txt`,
скрипты в `ci-scripts/`, примеры данных. Сейчас модуль перевода принимает один
документ за раз и семь расширений, а PDF превращает в текст, теряя вёрстку.

Образец, на котором согласован этот замысел, —
`DSB10_Intro_to_ML.ID_886521-master`: 19 файлов, 10 каталогов, 80 КБ.

## Решения

Приняты пользователем в разборе 26.10.2026:

1. **Выход архива** — перевод на месте: имена файлов сохраняются, содержимое
   заменяется переводом. Парных `_RUS`-файлов не создаём.
2. **Охват** — документы и конфиги целиком; в коде только комментарии и
   docstring. Не трогаем `LICENSE`, `CHANGELOG`, `.gitignore`, `.gitattributes`,
   `.gitkeep`, картинки и двоичное.
3. **Данные** (csv, tsv, json) — трогаем, только если наполнение русское.
   Английские заголовки колонок оставляем как есть; русские переводим вместе с
   содержимым. Это отменяет более раннее решение «переводить заголовки всегда и
   править код»: безопасный вариант получается сам.
4. **PDF** — на выходе снова PDF, с сохранением вёрстки.
5. **Объём** — разбор и смета до запуска, галочки по файлам, перевод по
   подтверждению.
6. **Куда встраиваем** — расширяем существующий модуль перевода, третьим
   источником рядом с «документ» и «видео». Отдельного модуля не заводим.

## Архитектура

### Реестр обработчиков

Контракт один на все форматы:

```python
@dataclass(frozen=True)
class TextUnit:
    unit_id: str        # устойчивый ключ внутри файла
    text: str           # что переводим
    hint: str = ""      # «заголовок», «комментарий», «ячейка» — контекст модели

class FormatHandler(Protocol):
    extensions: frozenset[str]
    def extract(self, content: bytes) -> list[TextUnit]: ...
    def apply(self, content: bytes, translations: dict[str, str]) -> bytes: ...
```

Существенное свойство: **`apply` получает исходные байты, а не собирает файл
заново**. Вёрстка сохраняется по построению — в DOCX подменяются текстовые узлы
XML, в XLSX строковые ячейки, в PDF блоки на своих координатах. Модель видит
только список строк и возвращает список строк; испортить файл она не может.

Между `extract` и `apply` — общий движок перевода: пакетирование, строгий
контракт `id → текст`, один форматный повтор при кривом JSON, учёт токенов. Он
уже написан как `_translate_docx_units`
(`src/content_factory/api/routers/document_translation.py:283`) и выносится
форматонезависимым.

### Раскладка

```
src/content_factory/translation/
    units.py            TextUnit, FormatHandler
    engine.py           перевод списка units (бывший _translate_docx_units)
    registry.py         расширение → обработчик
    language.py         определение языка наполнения по доле кириллицы
    report.py           сборка ПЕРЕВОД-ОТЧЁТ.md
    archive.py          распаковка, опись, смета, упаковка результата
    handlers/
        plain.py        md, markdown, txt
        html.py         html, htm
        docx.py         переезд существующего кода
        pptx.py         python-pptx
        xlsx.py         openpyxl
        pdf.py          PyMuPDF
        yaml_.py        PyYAML
        tabular.py      csv, tsv, json
        code.py         комментарии и docstring
```

`document_translation.py` (674 строки) худеет: из него уходят DOCX-механика и
цепочка `if extension ==`. Перевод одиночного документа становится частным
случаем архива из одного файла — один путь кода вместо двух.

## Поток архива

Существующая механика заданий подходит целиком и не меняется:
`POST /translate/document` возвращает `request_id` сразу,
`GET /translate/status/{id}` отдаёт `status`, `phase` и `progress`,
`GET /translate/download/{id}` — результат, владелец задания проверяется.

### Шаг 1 — разбор, без модели

`POST /translate/archive/inspect` принимает `.zip`, распаковывает во временный
каталог, прогоняет каждый файл через `extract` и возвращает опись:

```
plan_id, entries[]:
  path, handler, units, chars, selected: bool, skip_reason: str | None
totals: chars, estimate_seconds, estimate_usd
```

`extract` здесь работает вхолостую — считает единицы, ничего не переводя.
Побочная польза: битый файл всплывает до оплаты.

Смета считается по `input_cost_per_1m` и `output_cost_per_1m` текущей модели из
`src/content_factory/config/model_registry.yaml` и помечается как оценка.

По умолчанию отмечено всё переводимое, кроме файлов, уже написанных на целевом
языке. Методист снимает лишнее сам.

### Шаг 2 — перевод

`POST /translate/archive/{plan_id}/start` с отмеченными путями и языком →
`request_id`. Дальше существующие маршруты: `phase` — текущий файл, `progress` —
доля готовых. На выходе `.zip` с той же структурой и именами; непереведённые
файлы переносятся побайтно.

### Жизнь плана

Разобранный каталог живёт с ограничением по времени и числу планов, как
`_UPLOADS` в модуле РПД. План хранится в памяти процесса: перезапуск `cf-app`
его теряет, архив придётся загрузить заново. Распаковка идёт в файловую систему
контейнера, которая не лежит на томе, — результат нужно скачать, он не вечен.

## Обработчики

| Формат | Что извлекаем | Чем собираем |
|---|---|---|
| md, markdown, txt | весь текст | как есть |
| html, htm | текстовые узлы | как есть |
| docx | текстовые узлы `document.xml`, колонтитулов, сносок, примечаний | существующий код |
| pptx | текст фигур, таблиц, заметок докладчика | python-pptx |
| xlsx | строковые ячейки; формулы, числа, даты не трогаем | openpyxl |
| pdf | текстовые блоки с координатами и шрифтом | PyMuPDF |
| yml, yaml | только строковые значения, ключи никогда | PyYAML, порядок ключей сохраняем |
| csv, tsv, json | по правилу данных (ниже) | стандартная библиотека |
| код | комментарии и docstring | по правилу кода (ниже) |

### PDF

Блоки затираются и перевод вписывается в те же рамки. Русский длиннее
английского примерно на четверть, поэтому шрифт ужимается по ширине рамки, но не
ниже 70% исходного кегля — мельче текст становится нечитаемым. Не влезает и
так — блок остаётся на исходном языке и идёт в отчёт. Картинки и подписи не двигаются. Скан без текстового слоя — отказ на шаге
разбора, до оплаты.

### Код

Модель не получает код на правку. Ни строчки. Она видит только список
комментариев и возвращает их перевод; файл меняет код.

| Язык | Чем разбираем |
|---|---|
| Python | `tokenize` из стандартной библиотеки, docstring через `ast` |
| sh, bash | свой разбор: кавычки, `$'…'`, heredoc; шебанг `#!` не трогаем |
| js, ts, c, cpp, h, go, java | свой разбор: строки, символьные литералы, шаблонные строки, `/* */`, в JS регулярки |
| sql | `--` и `/* */` с учётом строк |
| остальное | пропускаем и пишем в отчёт |

**Инвариант, делающий это проверяемым:** после подстановки всё, кроме
комментариев, сравнивается с оригиналом побайтно. Совпало — файл принят. Не
совпало — файл откатывается к исходному и идёт в отчёт как непереведённый.
Разбор может ошибиться и пропустить комментарий, но не может испортить код: он
либо верен, либо отказ.

### Данные

1. Определяем язык наполнения по доле кириллицы в текстовых ячейках, по файлу
   целиком. Смешанный файл — по большинству, решение пишем в отчёт.
2. Наполнение английское — файл не трогаем вовсе.
3. Наполнение русское — переводим текстовые ячейки. Английские заголовки
   оставляем как есть, русские переводим.
4. Числа, даты, идентификаторы и коды не трогаем никогда.

Если русский заголовок менялся, строим карту `старый → новый` и заменяем в коде
**только строковые литералы, целиком совпадающие со старым заголовком** —
границы литералов даёт тот же разбор, что и для комментариев. Не подстрока, не
имя переменной, не комментарий. Каждая замена идёт в отчёт: файл, строка, что на
что. Случай редкий: код учебных проектов читает колонки по английским именам, а
они неприкосновенны.

## Пределы и безопасность

Архив приходит снаружи, поэтому проверки обязательны:

- путь внутри архива не выходит за корень (`../`, абсолютные пути, симлинки);
- отношение распакованного к упакованному ограничено — отсечка zip-бомбы;
- ограничение по числу файлов и суммарному размеру, сверх — отказ с понятным
  сообщением;
- расширение определяется по имени, содержимое не исполняется.

## Ошибки

Перевод одного файла, упавший с ошибкой, не роняет прогон: файл остаётся
исходным, причина идёт в отчёт. Отчёт кладётся в результат отдельным файлом
`ПЕРЕВОД-ОТЧЁТ.md`: что переведено, что пропущено и почему, какие колонки
переименованы, где блок PDF не влез, какие файлы не прошли проверку
неизменности кода.

## Тестирование

TDD, тест прежде кода. На каждый обработчик:

- «извлекли N единиц → подменили → файл открывается и содержит перевод,
  остальное побайтно на месте» — это же даёт проверку на невмешательство,
  которой сейчас нет;
- на код — злые случаи по каждому языку: `echo "# не комментарий"`,
  `url = "https://x"`, регулярка `/\/\//`, heredoc, docstring;
- на данные — английский файл не меняется ни на байт; русский переводится,
  английские заголовки сохраняются;
- на архив — путь с `../` отвергнут, zip-бомба отвергнута, непереведённые файлы
  переносятся побайтно;
- на поток — `inspect` не делает вызовов модели (проверяется подменённым
  клиентом), `start` отвечает сразу, статус доходит до `completed`.

## Порядок работ

Замысел великоват для одного захода, поэтому режется на части, каждая из которых
доходит до рабочего состояния и проверяется отдельно:

1. **Ядро.** `TextUnit`, `FormatHandler`, движок перевода, реестр. Переезд DOCX
   и текстовых форматов на новый контракт без единого изменения в поведении —
   существующие тесты модуля должны пройти как есть.
2. **Новые форматы по одному.** yaml → xlsx → pptx → pdf. Каждый со своим
   тестом на невмешательство; порядок по возрастанию сложности, pdf последним.
3. **Код и данные.** Разбор комментариев по языкам с инвариантом неизменности,
   правило языка наполнения, карта переименования колонок.
4. **Архив.** Распаковка с проверками, опись и смета, упаковка результата,
   отчёт.
5. **Страница.** Третий источник, экран сметы с галочками, прогресс по файлам —
   вся логика в `/static/js/`.

Части 1 и 2 полезны сами по себе: они чинят PDF и добавляют форматы для
одиночного документа ещё до того, как появится архив.

## Зависимости

Уже стоят: `pypdf`, `PyMuPDF` (`fitz`), `python-docx`, `openpyxl`, `PyYAML`.
Добавляется одна: **`python-pptx`**. В боевой контейнер ставится как ffmpeg —
`pip install` в работающий контейнер плюс строка в `requirements.txt`, иначе
пропадёт при пересборке образа.

## Чего не делаем

- Не переводим `LICENSE` — перевод лицензии юридической силы не имеет.
- Не создаём парные `_RUS`-файлы: решение 1.
- Не отдаём PDF как DOCX или Markdown: решение 4.
- Не правим код моделью.
- Не переводим английские данные и английские заголовки.
- Не храним планы и результаты дольше срока жизни — это рабочий инструмент, а не
  хранилище.

## Известные ограничения

- План разбора живёт в памяти процесса и теряется при перезапуске `cf-app`.
- Результат лежит в файловой системе контейнера, которая не на томе.
- Разбор комментариев для языков вне таблицы не делается — файл пропускается.
- Смета приблизительная: реальная цена зависит от длины перевода.
- Вся логика страницы идёт в `/static/js/`, а не внутрь HTML — иначе
  корпоративный прокси обрывает ответ, см.
  `docs/agent-memory/facts/corporate-tls-proxy.md`.
