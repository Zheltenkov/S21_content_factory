# Перевод документов: реестр обработчиков и правило «слоя до грамматики»

Записано 2026-10-26. Ветка `auditor-branch-dashboard`, коммиты от `5c2cc48` до `04b3973`.
На бой **не выложено** — договорились одним релизом в конце этапа.

## Что теперь устроено иначе

Модуль перевода больше не цепочка `if extension ==`. Есть контракт
(`src/content_factory/translation/units.py`): обработчик умеет `extract(bytes) -> [TextUnit]`
и `apply(bytes, переводы) -> bytes`. **`apply` получает исходные байты**, поэтому вёрстка
сохраняется по построению, а не потому, что модель вела себя прилично. Отсюда же проверка,
которой раньше не было: `apply(content, {}) == content` побайтно.

Реестр — `registry.py`. `page_extensions()` отбирает то, что предлагается на странице
одиночной загрузки: языки программирования в реестре есть ради архива, но на странице их
нет (`offered_on_page = False`).

Форматы: md/markdown/txt, html/htm, docx, xlsx, pptx (без `python-pptx` — не понадобился),
pdf (возвращается PDF с вёрсткой, а не голый текст), yml/yaml, csv/tsv, py и восемь языков
через tree-sitter.

## Правило, ради которого стоило всё это читать

Повторный разбор доказывает, что перевод не изменил код **в том виде, в каком его видит
грамматика**. У некоторых языков над грамматикой есть слой, работающий раньше неё: Java
разворачивает `u`-экранирование до разбора, C склеивает строки по обратной косой и читает
триграф `??/` как ту же косую, SQL экранирует ею кавычки, PostgreSQL вкладывает блочные
пояснения друг в друга. Проверка разбором этого увидеть не может.

Поэтому в переводе запрещены целиком, для всех языков: обратная косая, `??/`, `/*`, `*/`
(`FORBIDDEN_IN_TRANSLATION` в `handlers/code_treesitter.py`). Русское пояснение в них не
нуждается, а разбирать, какой слой что развернёт, — значит снова гадать.

Там же: `/*!…*/` у MySQL и `/*+…*/` у Oracle — это **код**, а не пояснение. Грамматика
зовёт их тем же узлом и ошибки не видит; перевести их значит испортить дамп.

И имя узла у грамматик разное: `comment`, `block_comment` у Java, `marginalia` у SQL.
Проверка по подстроке «comment» теряла блочные пояснения SQL целиком.

## Данные и язык наполнения

Правило принято пользователем: **комментарии переводим всегда, данные — только если
наполнение русское, а английские заголовки колонок оставляем**. Держится на одном
наблюдении: код учащегося читает колонку по имени, и `df['price']` должен продолжать
работать. Определение языка — `language.py`, по доле кириллицы среди букв.

## Перевод архива

Два шага нарочно: `POST /translate/archive/inspect` считает опись **без единого обращения
к модели** (тест с клиентом, который падает при вызове), возвращает смету по прайсу
`translator` из `model_registry.yaml`; методист снимает галочки;
`POST /translate/archive/{plan_id}/start` переводит только отмеченное.

Имя внутри архива — это слова архива о себе. Проверяется до чтения, отказ называет файл.
Отвергается: путь наружу, абсолютный путь, буква диска, пустая часть, символическая ссылка,
больше 2000 файлов, больше 64 МБ распакованного. Проверка обратной косой сегодня
недостижима через `zipfile` (тот нормализует её и при записи, и при чтении) — она оставлена
потому, что иначе защита зависела бы от этой нормализации, и проверяется прямым вызовом
`safe_archive_path`.

Прогон доходит до конца всегда: упавший файл остаётся исходным, причина идёт в
`ПЕРЕВОД-ОТЧЁТ.md` внутри результата. Исходов четыре и путать их нельзя — переведён,
пропущен, ошибка, **без изменений** (обработчик отказался, чтобы не испортить код).

План живёт в памяти процесса, привязан к пользователю (чужой `plan_id` отдавал бы опись
чужого архива), забывается по сроку, по числу и после прогона.

## Что нужно для боя

В контейнере `cf-app` понадобятся `tree-sitter` и `tree-sitter-language-pack` — ставятся как
ffmpeg, иначе перевод комментариев в коде не заработает. Пересоздавать `cf-app` только через
снимок — [[cf-app-writable-layer]].

Логика страницы архива лежит в `static/js/modules/translationArchive.js`, и контрактный тест
следит, чтобы её не вернули в страницу: [[corporate-tls-proxy]].

## Открытый вопрос к пользователю

В настоящем архиве курса лежат парой `README.md` (английский) и `README_RUS.md` (русский).
Опись отмечает русский — верно, но перевод по принятому правилу ляжет обратно в
`README_RUS.md`, а методист, вероятно, ждёт его в `README.md`. Не решено.
