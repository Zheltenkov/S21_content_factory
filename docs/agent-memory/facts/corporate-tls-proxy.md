19.10.2026 выяснилось, почему страница `/app/rpd` «не работает» у методистов, но
отвечает у всех, кто проверяет снаружи. `curl -v` с рабочего ноутбука показал
сертификат:

```
subject: CN=77-110-123-227.nip.io
issuer:  O=21-SCHOOL.RU; CN=Certificate Authority
```

Настоящий сертификат сервера — `C=US, O=Let's Encrypt, CN=YE2`. Значит соединение
сотрудника терминируется на корпоративном прокси, который расшифровывает TLS и
пересобирает его своим центром сертификации. Мы и они ходят к серверу разными
путями, поэтому «у меня работает» ничего не доказывает.

Как выглядит обрыв со стороны сервера (расширенный формат журнала, добавлен в тот
же день): запросы приходят и успешно обслуживаются, но браузер их не получает и
повторяет на новом соединении.

```
conn=279476:5  GET /app/rpd 200 4392 rt=0.018 ust=200
conn=279477:2  GET /app/rpd 200 4392 rt=0.013 ust=200
conn=279486:1  GET /app/rpd 200 4392 rt=0.016 ust=200
conn=279488:1  GET /app/rpd 200 4392 rt=0.019 ust=200
```

Четыре подряд, каждый за 13–19 мс, последние два — на свежих соединениях. В
браузере при этом `ERR_EMPTY_RESPONSE`. В `error.log` пусто, 5xx нет, контейнер без
рестартов.

**Почему:** `ERR_EMPTY_RESPONSE` означает, что соединение закрылось, не отдав ни
байта. Раз сервер ответ записал, а клиент ничего не увидел, обрыв происходит на
промежуточном узле — на том самом прокси. Смена соединения на каждую попытку —
почерк браузера, которому ответ обрезали.

**Как применять:** при жалобе «страница не работает» сперва попросить с того же
рабочего места `curl -sv <адрес> -o /dev/null` и посмотреть строку `issuer`. Чужой
центр сертификации означает прокси в середине, и дальше искать надо не в коде.
Решающий артефакт — в Chrome DevTools на неудачном запросе «Copy as cURL»: его
можно повторить и сравнить. Проверки с нашей стороны (сервер, домашняя сеть) этот
путь не воспроизводят.

**Что именно режет прокси — установлено пробами 19.10.2026.** На сервере были
подняты статические страницы `/probe/...`, которые методист открывал с рабочим VPN:

| Проба | Содержимое | Результат |
|---|---|---|
| короткий текст, 49 байт | — | прошла |
| 21 КБ HTML, со сжатием | — | прошла |
| 21 КБ HTML, без сжатия | — | прошла |
| то же, адрес содержит `rpd` | — | прошла |
| страница модуля целиком | со скриптами | **не прошла** |
| та же страница без скриптов | — | прошла |
| только скрипты страницы | — | **не прошла** |
| та же страница, скрипт отдельным файлом | — | прошла |
| встроен только блок загрузки УП | `XMLHttpRequest`, `upload.onprogress`, `FormData` | **не прошла** |
| встроен только блок Реестра | `fetch`, работа с DOM | прошла |

Итог: ни адрес, ни размер, ни сжатие ни при чём. Прокси обрывает ответ, внутри
которого есть `<script>` с кодом загрузки файлов — эвристика принимает его за
отправку данных наружу. Тот же код отдельным файлом проходит: внешние скрипты с
этого сервера (`/static/js/authSession.js` и прочие) у него грузятся всегда.

**Исправление** — коммит `69be43a`, выложено: скрипт главной страницы РПД вынесен
в `static/js/rpd-page.js`, скрипт страницы ожидания — в `static/js/rpd-waiting.js`
(номер прогона уходит в `data-run-id`, а не подставляется в код). Поведение не
менялось. Скрипт редактора оставлен внутри HTML: он только правит таблицы, и такой
код фильтр пропускает (проба Реестра).

Опыт с `gzip off` для `/app/rpd`, поставленный до проб, снят — пробы доказали, что
сжатие ни при чём.

Методист подтвердил 19.10.2026: с рабочим VPN модуль открывается. Пробы убраны —
каталог `/var/www/probe` удалён, блоки `location ^~ /probe/` из конфига сняты,
адреса отвечают 404. Расширенный формат журнала `cfdetail` оставлен: именно он
показал, что сервер отвечает за 15 мс, а браузер ответа не получает. Копии
конфига — `cf.conf.bak-20261019` (до формата) и `cf.conf.bak-gzip-20261019`
(до снятого опыта со сжатием).

**Как применять:** при жалобе «страница не работает у сотрудников, а у нас
открывается» сперва просить `curl -sv <адрес> -o /dev/null` с их рабочего места и
смотреть `issuer`. Чужой центр сертификации означает прокси в середине. Дальше не
гадать, а делить: выложить статические пробы, отличающиеся одним признаком, и
сужать по ответам. Четыре круга по три ссылки заняли полтора часа и дали точную
причину. И правило на будущее: **в этом приложении новый код страниц держать в
`/static/js/`, а не внутри HTML** — встроенные скрипты с загрузкой файлов до
сотрудников не доходят.
